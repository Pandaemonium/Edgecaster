PROCEDURAL MYTHS DESIGN
=======================

Purpose
-------
Procedural Myths are narrative artifacts generated from *real* player actions.
They are not random lore. They are post‑hoc interpretations of the player's
geometry, choices, and world impacts.

This system makes the world feel like it remembers the player. It converts
pattern history into legend fragments, murals, rumors, and codex entries.


1) Core Inputs: Myth Events
---------------------------
Each Myth Event is an action or milestone worth mythologizing.

Examples:
- SEAL_COMPLETED
- SEAL_FAILED
- BODY_SWAPPED
- ANCHOR_PLACED
- LEGENDARY_SLAIN
- PATTERN_EVOLVED (first time a resonance config achieved)
- CORRUPTION_PUSHED_BACK (region-level change)

Each event stores:
- event_id: unique id
- type: event type
- timestamp: game tick
- world_coord: (zone_x, zone_y, depth)
- actor_id: who caused it (player or NPC)
- pattern_signature: metrics (see below)
- context: hp, mana, time pressure, enemies nearby
- tags: list[str] (e.g., "near_death", "asymmetric")


2) Pattern Signature (Geometry Metrics)
---------------------------------------
These are computed from the PatternInstance that caused the event.

Suggested metrics:
- vertex_count, edge_count
- symmetry_score (0..1)
- average_edge_length
- baseline_angle
- resonance_tags (from chakra system)
- generator_source (chakra/tattoo/wand/shrine)
- shape_class: one of ["lattice", "forked", "radial", "serrated", "spiral"]

These metrics become the "mythic descriptors."


3) Feature Extraction
---------------------
Convert raw data into language tokens:

Geometry adjectives
- "crooked", "radiant", "fractured", "serrated", "nested"

Emotional tone (from context)
- "desperate" (low HP)
- "fugue" (high corruption)
- "triumphant" (fast, high score)
- "grim" (long fight, high enemy density)

Scope
- "local" (single zone), "regional", "world‑spanning"

Body motifs
- "borrowed spine" (body swap)
- "mirror‑arm" (resonance tags)


4) Myth Weaving
---------------
Myths are generated by selecting a template and filling tokens.

Template Types:
T1: Seal Legend
    "In {region}, the {adj_shape} seal held when {adj_tone} breath ran thin."

T2: Body Legend
    "They wore the {body_name} and cast the {shape_class} rune."

T3: Corruption Legend
    "The void recoiled as the {shape_class} cut the {corruption_style} veil."

T4: Relic Legend
    "The {artifact_name} hummed, and the edges aligned."

T5: Faction Rumor
    "The {faction} still whisper of the {epithet}."

Each myth has:
- title
- body (2–5 lines)
- tags
- location
- source_events


5) Myth Persistence
-------------------
Myths are stored in a MythLog:
- persistent across saves
- includes source_events for reproducibility
- can be surfaced multiple times in different contexts


6) Surfaces and Delivery
------------------------
1) Quest Journal tab: "Myths"
2) NPC Rumors: random pick of nearby myths
3) Murals / tablets: myth fragments at sites
4) World Map markers: myth icon for significant events

Optional: "Dream sequences" triggered by major seals.


7) Example Myth
---------------
Event: SEAL_COMPLETED, low HP, asymmetrical pattern, body swap.

Title: "The Crooked Seal"
Body:
    "At the Rim of Ash, a crooked lattice held when blood ran thin."
    "They wore a borrowed spine and carved a wound into the void."
Tags: ["asymmetric", "near_death", "possession"]


8) System Integration
---------------------
Hook points:
- seal_trials.py: emit SEAL_COMPLETED / SEAL_FAILED
- game.py: emit BODY_SWAPPED
- corruption.py: emit CORRUPTION_PUSHED_BACK
- pattern pipeline: compute PatternSignature
- quest journal: new Myth tab


9) Implementation Milestones
----------------------------
M1: Define MythEvent + MythLog schema
M2: Add PatternSignature computation
M3: Emit MythEvents at 3 core points (seal, body swap, anchor)
M4: Implement a small template library
M5: Add Myth tab to journal
M6: NPC rumor integration


10) Design Guardrails
---------------------
- Myths must reflect real player actions, not random strings.
- Templates should be short and distinctive (readable in UI).
- Avoid repetition: mark myths as "recently shown."
- Keep vocabulary consistent with the game's arcane‑math tone.
