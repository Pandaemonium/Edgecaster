Map Generation Strategy (Current Implementation)
------------------------------------------------

This document describes how the game currently generates:
- The global overworld "world map" (a Julia-set visualization of the full world).
- Each local overworld zone (a tile map the player walks around in).
- Phase 1 "corruption": a distortion field that changes the Julia iterator.

This is intended to be a shared reference for collaborators. If you touch map
generation, try to preserve these invariants unless you are deliberately
changing the design.


Core invariants (things we want to keep true)
---------------------------------------------
1) World map and local zones must remain "intimately tied".
   - A given global world tile coordinate always maps to exactly one Julia-plane
     coordinate (jx, jy).
   - Both the overmap renderer and local-zone generator must sample the same
     (jx, jy) for that tile.

2) Corruption is a modification of the Julia iterator (not a separate post-pass):

       z_{n+1} = z_n^2 + c + d(z_n)

   where d(z_n) is a deterministic distortion vector field in the complex plane.

3) Phase 1 corruption is "visual-only" for the overworld:
   - It changes the glyph/tint produced by Julia sampling.
   - It does NOT currently change walkability or destroy POI structures.
   - If corruption should affect walkability later, that is Phase 2.

Performance invariants (phase 1 goals)
--------------------------------------
1) The game should start without blocking on world-map rendering.
   - Overmap rendering is allowed to "pop in" when the player opens the world map.

2) Fast paths must not drift from canonical rules.
   - Numpy acceleration is encouraged, but it must route distortion math through
     the same corruption rules (distortion_np vs distortion_dz) so visuals remain
     deterministic and consistent.


Coordinate systems
------------------

World grid (tiles)
- The overworld is a grid of zones ("screens") of size:
    cfg.world_width  x  cfg.world_height
- The overworld has:
    cfg.world_map_screens x cfg.world_map_screens zones
- Global overworld tile coordinates:
    gx in [0, total_w-1], gy in [0, total_h-1]
  where:
    total_w = cfg.world_map_screens * cfg.world_width
    total_h = cfg.world_map_screens * cfg.world_height

Zone coordinates (screens)
- A zone coordinate is:
    (zx, zy, depth)
  For the overworld, depth == 0.

Julia plane (complex)
- Every global tile coordinate (gx, gy) maps to a Julia-plane coordinate (jx, jy).
- This mapping is driven by the current "overmap view" extents:
    overmap_params["view_min_jx"], overmap_params["view_max_jx"]
    overmap_params["view_min_jy"], overmap_params["view_max_jy"]
  and the chosen Julia constant:
    overmap_params["visual_c"]

Precomputed mapping arrays (tile_julia_grid)
- The Game builds two 1D arrays:
    game.tile_julia_grid["x"] length total_w
    game.tile_julia_grid["y"] length total_h
  such that:
    jx = xgrid[gx]
    jy = ygrid[gy]

This is the key mechanism that ties the global map and local zones together.


Where things live (code map)
----------------------------

Global map render:
- edgecaster/scenes/world_map_scene.py
  - WorldMapScene._render_overmap() draws the world map surface.
  - Holding ALT displays a "corruption field view" instead of the main map.
- edgecaster/overmap_accel.py
  - render_overmap_buffers_numpy() is the default/primary renderer for the overmap.
  - It vectorizes the Julia iteration across the whole low-res overmap grid.
  - It calls edgecaster.corruption.distortion_np so corruption rules are unified.

Local overworld generation:
- edgecaster/mapgen.py
  - generate_fractal_overworld() creates an overworld zone at depth 0.
  - refresh_fractal_overworld_visuals() updates an existing overworld zone's
    glyph/tint without touching structures (used when corruption changes).
  - apply_pois() applies POI IDs onto a world (world.poi_ids).
  - _julia_height_env_grid_numpy() computes a full (height, env) grid for a zone
    with numpy, instead of per-tile Python calls.

Overmap params, caching, and threading:
- edgecaster/game.py
  - Game._init_overmap_params_and_grid() selects overmap view + c and builds tile_julia_grid.
  - Game._start_world_map_thread() spawns a background render for the world map.
  - Game.world_map_cache holds rendered surfaces (main + ALT corruption view).
  - Game.set_corruption_level() and Game.add_corruption_hotspot() trigger
    refresh of existing zones and a world-map rerender.
  - IMPORTANT startup behavior:
    - The game does NOT render the world map during Game.__init__ anymore.
    - The world map is rendered lazily when the player opens it (pop-in is acceptable).

Corruption field (d(z)):
- edgecaster/corruption.py
  - CorruptionParams: tuning knobs (freq/amp/right_start/etc).
  - distortion_dz(): fast lookup for d(z) using precomputed LUTs.
  - julia_height_norm_corrupted(): escape-time sampling using z^2 + c + d(z).
  - distortion_np(): numpy analogue of distortion_dz(), used by overmap_accel.py
    and local-zone numpy generation so the rules cannot drift.


World map generation (WorldMapScene._render_overmap)
----------------------------------------------------
The world can be huge in tiles (total_w * total_h), so the overmap is rendered
at a lower resolution and then scaled up to fit the window.

High-level pipeline:
1) Determine render resolution
   - Current approach (subject to tuning):
       target_w = max(640, renderer.width - 64)
       target_h = max(480, renderer.height - 180)
       render_scale = 0.5
       px_w = max(320, int(target_w * render_scale))
       px_h = max(240, int(target_h * render_scale))

2) Choose the Julia view extents and c
   - Uses game.overmap_params when present; otherwise picks a curated entry.
   - These extents are the authoritative basis for tile_julia_grid.

3) Compute low-res overmap buffers (main map + ALT corruption view)
   - Default path (fast): edgecaster/overmap_accel.py:render_overmap_buffers_numpy()
     a) Map pixel -> global world tile index:
          wx_map[px] in [0..total_w-1]
          wy_map[py] in [0..total_h-1]
     b) Map global world tile -> Julia coord:
          jx = tile_julia_grid["x"][wx]
          jy = tile_julia_grid["y"][wy]
        (if the grid is missing, it falls back to interpolation from view extents)
     c) Vectorized Julia iteration across the whole pixel grid:
          z_{n+1} = z_n^2 + c + d(z_n)
        where d(z) is computed by corruption.distortion_np().
     d) Produce:
        - rgb_main: the final overmap color buffer (uint8 RGB)
          (currently: smooth palette from height + simple hillshading for relief)
        - rgb_corr: the ALT corruption field view (uint8 RGB)
        - peak_env: the envelope strength (float32) used for debugging/ALT view
   - Fallback path (slow, should be rare): WorldMapScene._render_overmap() can still
     do per-pixel Python sampling if numpy is unavailable:
       - classify tile -> biome index via mapgen._classify_tile()
       - map index -> color via WorldMapScene._biome_color_by_index()

4) Important: the main map does NOT directly visualize corruption by tinting
   - Corruption is visible because it changes the Julia escape-time height.
   - Corruption field visualization is available only via ALT view.

5) ALT corruption view (WorldMapScene)
   - The ALT view visualizes the *distortion field at z0* (the Julia coordinate of
     that world tile), not the full escape-time height.
   - Encoding:
     - R channel roughly encodes dx (real distortion direction).
     - B channel roughly encodes dy (imag distortion direction).
     - G channel encodes the local envelope strength.
   - Fast path: overmap_accel computes this by vectorizing corruption.distortion_np()
     over the entire z0 grid and returning rgb_corr.
   - Fallback path: world_map_scene computes this by calling corruption.distortion_dz()
     per pixel when ALT is held.

6) Scale low-res surfaces up to the final map size:
   - pygame.transform.smoothscale() to (target_w, target_h)

7) Cache results:
   - Game.world_map_cache stores:
       surface       (main map)
       surface_corr  (ALT corruption field view)
       view params and cache key

8) Threading:
   - The overmap render happens on a background thread from Game._start_world_map_thread().
   - A version counter (Game.world_map_version) ensures stale renders are discarded.
   - While rendering, WorldMapScene shows:
       - "Generating world map..." (initial render)
       - "Corruption reverberating..." (rerender due to corruption changes)
   - Startup optimization:
     - Game.__init__ no longer starts the world-map thread.
     - WorldMapScene starts the thread lazily when the player opens the world map.

Temporary tuning UI:
- The world map currently has a temporary slider (top-left) that sets
  game.corruption_level and triggers a rerender on mouse-up.


Local overworld zone generation (mapgen.generate_fractal_overworld)
------------------------------------------------------------------
When generating an overworld zone (depth 0):

1) Compute this zone's global tile offsets:
   - cx0 = zx * world.width
   - cy0 = zy * world.height

2) Get the Julia coordinate slices for this zone:
   - jx_slice is xgrid[gx0:gx1] where gx0 = zx*world_width
   - jy_slice is ygrid[gy0:gy1] where gy0 = zy*world_height

3) For each local tile (x, y):
   - jx = jx_slice[x]
   - jy = jy_slice[y]
   - Sample escape-time height with corruption:
       (h_val, corr) = _julia_height_norm_with_corruption(jx, jy, visual_c, ...)
   - Convert height/moisture to a terrain glyph using _classify_tile().
   - Convert fields to a base color using _color_from_fields().
   - (Currently) apply a subtle corruption tint for local-zone tiles using corr.
   - Set tile fields:
       tile.glyph, tile.walkable, tile.tint

Performance note (local zone generation):
- The implementation now prefers a numpy grid fast-path:
    mapgen._julia_height_env_grid_numpy(...)
  which computes the full (height, corruption_env) arrays for the zone in one
  vectorized iteration loop.
- This keeps exact local/world correspondence because it operates on the exact
  per-tile Julia coordinates in jx_slice/jy_slice (from tile_julia_grid).
- The scalar per-tile path remains as a fallback if numpy errors or is missing.

Note on walkability:
- The overworld is intentionally open right now:
  - tile.walkable is forced True in generate_fractal_overworld().
  - water glyphs ("~") are replaced to "." for traversal.
- POIs and explicit structures can introduce blockers (doors/walls/etc).

Refreshing existing overworld zones when corruption changes:
- Game._refresh_corruption_visuals() calls mapgen.refresh_fractal_overworld_visuals()
  for every already-instantiated depth-0 zone.
- That function recomputes glyph+tint but skips "protected" tiles (e.g. depot walls).


Corruption (Phase 1) details
----------------------------
Corruption changes the Julia iteration rule used to compute height:

  Standard:
    z_{n+1} = z_n^2 + c

  Corrupted:
    z_{n+1} = z_n^2 + c + d(z_n)

Where d(z) is a deterministic vector field in the complex plane:
  d(z) = amp * env(z) * (nx(z) + i * ny(z))

Key pieces:
1) CorruptionParams (edgecaster/corruption.py)
   - freq: base frequency of the underlying noise field
   - amp: distortion amplitude (before envelope scaling)
   - right_start/right_sharpness/right_weight: concentrates the distortion on the right side
   - spot_freq/spot_threshold/spot_weight: scattered peaks (rare spikes), but gated by the right-side cloud by default
   - hotspots: explicit Gaussian bumps (jx, jy, strength, sigma)

2) distortion_dz() performance strategy
   - During iteration, we only evaluate d(z) while |z| <= 2, so we precompute LUTs
     over z in [-2, 2] x [-2, 2].
   - _noise_lut() builds (and caches, lru_cache):
       - a mountain-like heightfield H via fBm + ridges
       - its gradient (nx_tex, ny_tex) as a coherent vector field
       - a spots_tex for scattered peaks (later gated by the right-side cloud)
   - _anchor_lut() builds (and caches) a multiplicative suppression mask for rune anchors.
   - distortion_dz() does nearest-neighbor sampling of these textures for speed.
   - Recent performance work:
     - _noise_lut and _anchor_lut now use a numpy vectorized implementation when numpy
       is available, and fall back to the pure-Python implementation otherwise.
     - This change is critical for fast startup because local-zone generation and the
       overmap both need the LUTs.

3) "Mountains of corruption"
   - These are peaks/ridges in the distortion FIELD (d(z)), not a literal height boost.
   - In _noise_lut(), a left->right mask is applied to the entire heightfield so the far-left is
     mathematically flat (and thus has d(z)=0), while ridges grow stronger to the right.
   - The start of that mask is tied to CorruptionParams.right_start (0..1).

4) Hotspots ("corruption cones")
   - Game.corruption_hotspots stores (jx, jy, strength, sigma) bumps.
   - They are converted into a LUT (hot_tex) and added to env(z).
   - Hotspots also contribute a direction field derived from grad(hot_tex) so they
     can distort even in regions where the base mountain field is masked to zero.


Key tuning knobs (where to edit)
--------------------------------

Global intensity (per run, runtime changeable):
- edgecaster/game.py:
    Game.corruption_level
    Game.set_corruption_level(...)

Corruption field shape (code-level tuning):
- edgecaster/corruption.py:
    CorruptionParams.freq
    CorruptionParams.amp
    CorruptionParams.right_start / right_sharpness / right_weight
    CorruptionParams.spot_* (scattered peaks)
    CorruptionParams.base_res / detail_res / ridge_strength (landscape builder look)
    CorruptionParams.mount_mag_floor / mount_mag_ceil (valleys vs mountains shaping)
    _LUT_RES (texture resolution for d(z) lookup)

Performance/fast-path notes:
- The codebase uses numpy opportunistically for performance:
  - world map: edgecaster/overmap_accel.py
  - local zones: edgecaster/mapgen.py (_julia_height_env_grid_numpy)
  - LUT construction: edgecaster/corruption.py (_noise_lut / _anchor_lut)
- If numpy is not installed, the game should still run, but:
  - world map rendering becomes much slower
  - local zone generation can stall startup
  - corruption LUT construction becomes expensive

Temporary UI (for experimentation):
- edgecaster/scenes/world_map_scene.py:
    slider_min / slider_max (currently 0..2)


Future (Phase 2) notes
----------------------
If corruption should change walkability / structures:
- We will need to either:
  - regenerate zones (or parts of them) when corruption changes, OR
  - introduce a second "overlay" layer whose walkability rules depend on corruption.

Phase 1 already has the wiring for:
- "visual refresh" of instantiated overworld zones
- a background world-map rerender on corruption changes

Phase 2 should extend that refresh pipeline carefully.
