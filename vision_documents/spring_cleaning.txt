STAGE 3 — ATTENTION FIELD CACHING (Future)

Goal: Replace vestigial zones with dynamic, scale-aware attention field.
What's "hot" (near camera + similar scale) gets realized; rest is abstracted.

[VISION] Design attention field data structure
  - Spatial/scale heatmap centered on observer
  - Nested grid keyed by scale level
  - "Hotness" determines simulation fidelity

[VISION] Deterministic realization/coarsening
  - Hot regions spawn/realize detailed entities
  - Cold regions coarsen to aggregates
  - Transitions must be deterministic (same seed = same result)

[VISION] Persistent delta system
  - Changes to world must persist when region goes cold
  - Berry picked = patch remembers depletion
  - Bear killed = stays dead (unless designed otherwise)
  - Entity displacement persists across hot/cold cycles

[VISION] Scale-dependent bucket caching
  - Performance caches must be scale-aware
  - A Leviathan spans many "zones" - old rigid rectangles don't work
  - Tiny entities exist within footprint of coarse tiles

-------------------------------------------------------------------------------
STAGE 4 — MACRO ENTITY HIERARCHY (Future)

Goal: Entities can resolve into sub-entities and coarsen back into aggregates.
First-class support for multi-scale entities: armies, cities, forests.

[VISION] Entity resolution/coarsening system
  - forest → woods → trees → berry patches → berries
  - city → districts → buildings → walls → NPCs
  - army → battalions → squads → individuals

[VISION] Aggregate entity representation
  - Coarse entities carry summary stats (strength, morale, resources)
  - Resolution spawns detailed entities from aggregate state
  - Coarsening computes aggregate from detailed state

[VISION] Sub-entity spawning rules
  - Define resolution triggers (proximity, zoom, attention)
  - Ensure bidirectional consistency (resolve then coarsen = original)
  - Handle partial resolution (edge of attention field)

-------------------------------------------------------------------------------
STAGE 5 — SCHEDULING / SIMULATION BUDGET (Future)

Goal: Global energy queue with attention-dependent tick granularity.
High fidelity near observer, abstract resolution far away.

[VISION] Attention-based simulation fidelity
  - Nearby entities tick every frame
  - Distant entities tick less frequently or as dice-roll outcomes
  - Scale matters: crickets tick when zoomed in, not zoomed out

[VISION] Abstract event resolution
  - Far-away battles resolve as aggregate outcomes
  - Time skips apply abstract rules, not full simulation
  - Results should be deterministic given same seed

[VISION] Body-swap / observer migration
  - Camera/attention follows inhabited actor, not "player entity"
  - Old vessel persists in world (cold simulation)
  - Return to vessel: it's still there (modulo time/events)
  - Entity data model same for player and NPCs

-------------------------------------------------------------------------------
YOGA DEBUG HEURISTICS

Use these to smell yoga violations during development:

1. "Flies in from upper-left"
   → UI using zone-local or uninitialized coords

2. Mouse and keyboard disagree
   → Two coordinate conversion paths; one double-converts or clamps

3. Things change at zone boundaries
   → Canonical state still zone-owned; view->truth commit missing

4. Overlays exist logically but not visually
   → Stored data overwritten by canonical sync, or wrong coord frame

5. "Always chooses the rightmost vertex"
   → Nearest-neighbor running in wrong coordinate space (ABS vs local)
