1. PROJECT OVERVIEW & CORE CONCEPT
===============================================================================

**What is Edgecaster?**
A turn-based roguelike where you play as the last Patterncaster in a world where
ancient seals have failed and demons are infiltrating. You draw and manipulate
fractal rune patterns as your primary magic system, traveling the world to remake
seals and push back demonic influence.

**Core Innovation:**
Fractal-based magic where players:
- Place terminus anchors on tiles
- Apply fractal generators (Koch, Branch, Zigzag, custom-drawn patterns)
- Activate patterns to deal damage based on graph geometry
- Gate complexity by INT/RES stats (coherence/strength limits)

**Technical Foundation:**
- Language: Python 3.x with dataclasses
- Framework: Pygame-ce (community edition)
- Dependencies: Minimal (pygame-ce, pyyaml)
- Scale: ~33,000 lines of Python across 70 files
- Platform: Windows launcher provided, but Python is cross-platform

**Genre & Style:**
Traditional roguelike with:
- Turn-based tactical combat
- Procedurally generated dungeons/world
- Permadeath (with save system)
- ASCII graphics with sophisticated visual effects
- Deep mechanical systems (stats, factions, status effects)

**Turn Flow:**
```
1. Game.advance_turn() called from DungeonScene
2. Scheduler.pop_next() → (time, actor_id, action_callback)
3. Action executes (move, attack, cast, wait, etc.)
4. Results applied to level state (HP changes, position updates, etc.)
5. AI chooses actions for NPCs that just took their turn
6. Pattern TTL decremented, status effects processed
7. Messages logged, UI updated
8. Repeat until player's turn
```

7. PATTERN/FRACTAL MAGIC SYSTEM (THE HEART)
===============================================================================

**Core Concept:**
Players draw rune patterns using fractal generators, then activate them for
area damage. Pattern complexity is gated by INT (coherence) and RES (strength).

**Pattern Data Model (state/patterns.py):**

```python
@dataclass
class Pattern:
    vertices: List[Vertex]  # Nodes in pattern graph
    edges: List[Edge]       # Connections between nodes
    meta: Dict[str, Any]    # Metadata (color schemes, etc.)

@dataclass
class Vertex:
    pos: Tuple[float, float]  # World-space position
    color: Tuple[int, int, int]
    power: float               # Damage contribution

@dataclass
class Edge:
    a: int  # Vertex index
    b: int  # Vertex index
    color: Tuple[int, int, int]
    weight: float  # Damage contribution
```

**Fractal Generators (patterns/builder.py):**

All generators transform `List[Segment]` → new `List[Segment]`:

1. **SubdivideGenerator:**
   - Splits each segment into N equal parts
   - Linear subdivision (no deformation)

2. **KochGenerator:**
   - Classic Koch snowflake-style bumps
   - Configurable bump height and direction

3. **BranchGenerator:**
   - Tree-like branching from segment midpoints
   - Configurable branch angle and length

4. **ZigzagGenerator:**
   - Angular deformations (sawtooth, square wave)
   - Configurable amplitude and frequency

5. **CustomPolyGenerator:**
   - User-drawn patterns from character creation
   - Amplitude scaling for size control
   - Shape templates (polylines drawn on grid)

**Generator Chain Pattern:**
```python
pattern = line_pattern(start, end)
for _ in range(iterations):
    segments = pattern.to_segments()
    segments = generator.apply_segments(segments, max_segments)
    pattern = Pattern.from_segments(segments)
```

**Pattern Lifecycle:**

1. **Placement:**
   - Player selects "place_terminus" action
   - Targets a tile (becomes anchor point)
   - Pattern graph initialized with anchor vertex

2. **Generation:**
   - Player selects fractal generators from character sheet
   - Each generator applied iteratively
   - Coherence check: vertex count ≤ INT-based limit
   - Pattern stored in level.pattern_vertices/edges

3. **Activation:**
   - Player selects "activate_all" or "activate_seed"
   - project_vertices() converts graph → world-space positions
   - damage_from_vertices() calculates area damage
   - Strength check: damage scaling by RES-based limit
   - Damage applied to all actors in range

4. **TTL & Cleanup:**
   - Patterns have activation TTL (default: 10 turns)
   - Decrement each turn, fade out when TTL → 0
   - Can be refreshed by re-casting

**Coherence/Strength Gating (config.py):**
```python
coherence_limit = base_limit * (1 + INT_bonus)
strength_limit = base_limit * (1 + RES_bonus)
```

This creates a progression curve where high-INT characters can draw more
complex patterns, and high-RES characters can amplify damage output.

**Pattern Activation Systems:**

- **patterns/activation.py:**
  - project_vertices(pattern, anchor_pos) → world positions
  - damage_from_vertices(vertices, edges, target_pos) → damage value
  - Geometric algorithms for range/AoE calculation

- **patterns/queries.py:**
  - Graph traversal utilities
  - Neighbor finding, connected components
  - Distance calculations on pattern graphs

- **patterns/library.py:**
  - Preview generation for UI (ability bar icons)
  - action_preview_geometry() for ability tooltips

- **patterns/motion.py:**
  - Pattern animation (rotation, pulsing, etc.)
  - Visual feedback during activation

- **patterns/colors.py:**
  - Color scheme generation for patterns
  - Gradient interpolation, hue shifting

9. TURN SCHEDULING & COMBAT
===============================================================================

**TurnScheduler (systems/turns.py):**

Heap-based priority queue for turn order.

```python
@dataclass
class TurnScheduler:
    queue: List[Tuple[int, int, str, Callable]]  # (time, tiebreak, actor_id, callback)

    def schedule(self, delay: int, actor_id: str, callback: Callable):
        heapq.heappush(self.queue, (current_time + delay, tiebreak, actor_id, callback))

    def next(self) -> Tuple[int, str, Callable]:
        time, _, actor_id, callback = heapq.heappop(self.queue)
        return time, actor_id, callback
```

**Turn Flow:**
```
1. Player acts (move, attack, cast, etc.)
   ↓
2. game.queue_player_action(action, **params)
   ↓
3. scheduler.schedule(delay, player_id, action_callback)
   ↓
4. game.advance_turn() loops:
   - pop next action from scheduler
   - execute action callback
   - apply results (damage, movement, status effects)
   - AI chooses next action for that actor
   - schedule AI action with delay
   ↓
5. Repeat until player's next turn
```

10. CORRUPTION SYSTEM (JULIA-SET DISTORTION)
===============================================================================

**Core Concept:**
Terrain distortion via deterministic chaos (Julia-set iteration). Rune anchors
suppress corruption locally, creating "safe zones."

**Physics (corruption.py - 1,228 lines):**

Julia iterator:
```
z_{n+1} = z_n^2 + c + d(z)
```

Where:
- `z`: Complex position in world-space
- `c`: Julia set constant (configured per world)
- `d(z)`: Distortion vector field (Perlin-like noise + hotspots)

**Distortion Sources:**
1. **Global Intensity:** `game.corruption_level` (0.0 → 1.0)
2. **Hotspots:** Explicit corruption peaks at specific world positions
3. **Rune Anchors:** Gaussian suppression zones around active patterns

```python
suppression = 1 - strength * exp(-||z - anchor||^2 / (2σ^2))
```

**Corruption Application:**

1. **World Map Rendering (overmap_accel.py):**
   - Julia iteration distorts terrain height/color
   - Creates "mountains of corruption" on right side of map
   - Anchors create visible "calm zones"

2. **Local Zone Generation (mapgen.py):**
   - Terrain glyph/color modulation based on corruption
   - Biome transitions warped by distortion field
   - Enemy spawn rates influenced by corruption level

3. **Visual Effects:**
   - Screen tint (reddish hue in high-corruption zones)
   - Scanline/glitch effects
   - Entity color shifts (corrupted creatures)

**Corruption State:**
```python
@dataclass
class CorruptionParams:
    level: float                       # Global intensity (0.0 → 1.0)
    hotspots: List[Hotspot]            # Explicit peaks
    anchors: List[RuneAnchor]          # Suppression zones
    julia_c: complex                   # Julia constant
    seed: int                          # RNG seed for noise
```

**Performance:**
- Lookup tables for Julia iteration (pre-computed grids)
- Gaussian anchor suppression (cached distance fields)
- Right-side bias for "mountains of corruption" (world shaping)

```
Scene declares effect names: ["clockwise", "fiery"]
  ↓
visual_effects.build_visual_profile(effects, time)
  ↓
Geometry transforms applied to VisualProfile
  ↓
apply_visual_panel(surface, profile) → transformed surface
  ↓
Color modulation applied to entity glyphs
  ↓
draw_overlay() renders screen-space effects
  ↓
screen_tint() applies full-screen color tint
```

**Effect Stacking:**
Effects intentionally stack and compose:
```python
effects = ["mirror_x", "clockwise", "ghostly"]
# Result: mirrored, then rotated, then translucent
```

**Global vs Scene-Local:**
- Global effects (e.g., "cursed world mirror_x") applied to entire renderer
- Scene effects applied to entities within that scene
- Entity effects applied to individual sprites/glyphs

===============================================================================
14. COMMON DEVELOPMENT PATTERNS
===============================================================================

**1. Dataclass-Heavy Design:**
Almost all state is modeled with @dataclass:
```python
from dataclasses import dataclass

@dataclass
class Character:
    name: str
    class_name: str
    stats: Stats
    generators: List[str]
    custom_pattern: Pattern | None
```

Benefits: Clear structure, auto-generated __init__, easy serialization.

**2. Prototype/Template Pattern:**
Content is data-driven via YAML with inheritance:
```python
proto = prototypes.resolve_proto("imp")  # Resolves parent chain
actor = spawn_factory.build_actor_from_spec(proto)
```

**3. Action Registry Pattern:**
Actions are declarative and registered globally:
```python
@register_action
def melee_attack(game, actor_id, target_id):
    # ... implementation ...
    pass
```

**4. Scene Stack Architecture:**
Scenes are pushed/popped on a stack:
```python
manager.push(InventoryScene(game))  # Overlay on top
# ... user closes inventory ...
manager.pop()  # Back to DungeonScene
```

**5. Generator Chain Pattern:**
Fractal generators transform segment lists:
```python
for gen in generators:
    segments = pattern.to_segments()
    segments = gen.apply_segments(segments)
    pattern = Pattern.from_segments(segments)
```

**6. Visual Effects as Composable Traits:**
Effects are registered by name and composed:
```python
entity.tags["visual_effects"] = ["fiery", "ghostly"]
# Renderer applies both effects in order
```

**7. Event-Driven Architecture:**
Input → GameCommand → Action → State Update:
```python
pygame_event → GameInput.parse() → GameCommand
  → DungeonScene.handle_event(command)
    → game.queue_player_action(action, **params)
```

**8. Functional Core, Imperative Shell:**
- Pure functions for: damage calculation, pattern generation, coordinate transforms
- Imperative shell for: game loop, rendering, input handling, state mutations

**9. Caching & Lazy Evaluation:**
- Prototype resolution cached after first load
- LoD terrain cached by (region, zoom, params)
- Pattern previews generated on-demand

**10. Separation of Concerns:**
- Scenes: Input interpretation, UI flow
- Systems: Game logic (AI, targeting, effects)
- State: Data structures (entities, world, patterns)
- Render: Pure view layer (draw-only)
